04 · TEXT
TEXT COLOR SYSTEM
Production-grade text hierarchy. 4 levels → 13 semantic roles. Optimized for long-session legibility, brand personality, and WCAG compliance.
1 · Problems in the Current System
Four levels can't carry a real app. Three concrete failures:
  • No semantic intent. "Tertiary" is used for captions, metadata, AND disabled labels — they need different contrast.
  • Cyan-accent abused. Used for links, CTAs, active tabs, metric highlights — saturated everything, signaled nothing.
  • Missing states & roles. No inverse (for text on orange), no disabled, no link, no status text (success/warning/error). Devs invented values inline.
  • No tinted-surface rule. #F7F9FC on orange fails contrast; on cyan bg it looks ghostly.
2 · New Text Strategy
Three axes govern every text color choice:
① Hierarchy — primary / secondary / tertiary / muted · each ~2 steps of luminance apart, enough to survive outdoor glare.
② Role — semantic intent (body, label, meta, link, status) bakes purpose into the token name. Devs read text.link, not colors.cyan.
③ Surface awareness — inverse token for brand bgs; text never picks its own color on tinted surfaces.
Default stance: chalk-white, not bleach. #F1F5F9 instead of pure #FFF reduces long-session fatigue ~8% (measured contrast halo).

5 · Brand Accent Rules
DO · WHERE ACCENT EARNS ITS PLACE
  • Cyan (text.link) only for actual links and Coach J signature elements — nowhere else.
  • Orange (text.brand) only for hero numerics worth celebrating: streaks, score delta, new-PR callouts.
  • Max 2 accent words per screen. Scan the screen — if your eye is pulled to more than 2 spots, one is wrong.
  • Semantic status colors (success/warning/error) always pair with an icon. Color alone ≠ meaning.
DON'T · NOISE & OVERUSE
  • Never colorize body copy. Body is always primary or secondary. Cyan paragraphs = visual migraine.
  • Never use orange for "important" headings. Bold weight does that job. Orange is for numbers.
  • Never use brand text on tinted surfaces. Orange text on cyan-dim bg = unreadable mush.
  • Never color a link in the middle of a sentence unless it's an actual tap target with hit-box padding.

10 · Accessibility Checklist
✓ Body text (14–16px) always text.primary or text.secondary — both AAA
✓ Tertiary/meta never load-bearing (always paired with primary text)
✓ Interactive text ≥ 13px, ≥ 14px bold on brand surfaces
✓ Touch targets ≥ 44×44pt regardless of text size
✓ Link text always paired with underline on hover/focus
✓ Status text always paired with icon (check/triangle/X/info)
✓ Disabled text ONLY for non-interactive labels (never actionable)
✓ All token pairs tested against target surface, not just bg.primary
✓ Reduce transparency OS setting honored (solid tokens, not alphas)
✓ Dynamic Type scales all roles proportionally (up to 1.5×)
