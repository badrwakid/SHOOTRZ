2 · Replacement Pattern · Components & Screens
✗ BEFORE · raw hex
// Button.tsx const styles = StyleSheet.create({ cta: { backgroundColor: '#E8521A', // ← raw shadowColor: '#E8521A', }, label: { color: '#FFFFFF' } })
✓ AFTER · semantic token
// Button.tsx import { useTokens } from '@/theme' const t = useTokens() const styles = StyleSheet.create({ cta: { backgroundColor: t.brand.orange.base, shadowColor: t.brand.orange.base, }, label: { color: t.text.inverse } })
Rule: components never import colors directly. They call useTokens() which returns the resolved v3 token tree. This lets us flip light/dark, swap themes per user, or adjust a brand color globally in one place.
3 · Lint & Design Guardrails
✗
no-raw-brand-hex — ESLint rule blocks any literal #E8521A, #EC5A28, #00D4FF, #14C7E0 in component files. Forces semantic imports.
✗
no-hardcoded-colors — blocks color: '#hex' / backgroundColor: 'rgb(...)' outside theme/. Allowed in theme/tokens.ts, *.stories.tsx, and tests.
✓
token-contract — CI fail if tokens.json diverges from shootrz.tokens.json · v3. Single source of truth, versioned.
✓
a11y-contrast-check — Storybook addon runs Axe on every component; orange-on-white small text gets flagged for users to resize or swap to chrome.
✓
figma-tokens-sync — Token Studio pipeline publishes the same JSON to Figma variables. Designers consume the same tree devs do.
