\subsection{Frontend Tests}

Jest~29 with React Native Testing Library powers the frontend test suite. Contract tests (\lstinline|tokens.contract.test.ts|) verify that design token references in components match the token registry, preventing silent name typos. UI tests verify layout and accessibility for core screens.

\subsection{Load Tests}

Locust scenarios (\lstinline|backend/tests/load/locustfile.py|) simulate concurrent video uploads up to the semaphore limit of~8, validate that jobs beyond the limit receive HTTP~429, and measure end-to-end pipeline latency distribution under sustained load.

\section{Evaluation Metrics}
\label{sec:evaluation_metrics}

\subsection{Implemented Metrics}

\textbf{Shot Detection Coverage.}
The \lstinline|ShotDetector| outputs a confidence score in $[0, 1]$ for each detected event. On the development test corpus (synthetic and real clips), the fused multi-signal detector correctly identifies the release frame within $\pm 5$ frames of the manually annotated ground truth in the majority of test cases. No formal aggregate precision/recall has been computed over a labelled dataset, as constructing such a dataset at scale was outside the project scope.

\textbf{Pose Estimation Coverage.}
Measured as the fraction of frames passing the 0.40 mean-visibility threshold. On typical indoor basketball clips (good lighting, unobstructed body), coverage is generally above 85\%. Poor lighting or heavy occlusion reduces coverage below 60\%, which the system surfaces in the \lstinline|quality_warnings| field of the result.

\textbf{Scoring Distribution.}
The geometric mean scoring produces scores in the range 30--80 for typical amateur players. Elite-form clips recorded against published benchmark videos score above 85. The Gemini AI score override adds approximately 10--15 points in cases where the geometric mean is suppressed by a single low-confidence metric axis, providing a more practical coaching-oriented assessment.

\subsection{Proposed Future Metrics}

The following evaluation approaches are identified as targets for rigorous future evaluation and are not presented as completed measurements:

\begin{itemize}
  \item \textbf{Shot Detection Accuracy:} Label a corpus of 200+ basketball shot videos with ground-truth release frames ($\pm 2$ frames), then measure detection error distribution and phase classification accuracy across STANCE, CROUCH, RELEASE, and LANDING events.
  \item \textbf{Metric Validity:} Validate computed elbow and knee angles against instrumented measurements (goniometer or Vicon motion capture) on a small set of consenting subjects.
  \item \textbf{Recommender Evaluation:} A/B test FAISS-only versus FAISS + LinUCB recommendation, measuring downstream improvement in mechanical scores after drill completion.
  \item \textbf{LLM Feedback Quality:} Expert-rater evaluation of Gemini-generated coaching cues for technical accuracy, specificity, and actionability.
\end{itemize}

With 8 concurrent process slots and a mean pipeline duration of 20 seconds, the system sustains approximately 24 analysis jobs per minute under sustained concurrent load, which is sufficient for the expected usage pattern of a mobile application in early deployment.

\section{Results}
\label{sec:results}

\subsection{Achieved Functionality}

The following capabilities are fully implemented, tested, and functional in the submitted codebase:

\begin{itemize}
  \item \textbf{Six-stage analysis pipeline}: VideoLoader $\rightarrow$ PoseEstimation $\rightarrow$ SignalSmoothing $\rightarrow$ ShotDetection $\rightarrow$ AngleComputation $\rightarrow$ MetricsDerivation runs end-to-end on real smartphone video, producing scored metrics and an annotated overlay video in under 30 seconds on a four-core server.
  \item \textbf{Normative scoring tied to published research}: All five metric thresholds are sourced from Cabarkapa et al.~\cite{Cabarkapa2021}, Okazaki et al.~\cite{Okazaki2012}, and Struzik et al.~\cite{Struzik2014}, with separate target bands for beginner, intermediate, and advanced players.
  \item \textbf{Two-layer scoring}: The deterministic geometric mean score is preserved as the fallback. When Gemini is available, a holistic AI score is computed and the \lstinline|ai_scored| flag distinguishes the two in the API response.
  \item \textbf{Conversational coaching with history context}: The chat endpoint injects the user's recent metrics, skill level, and weak areas into the Gemini prompt via the \lstinline|get_coach_context| RPC before each response.
  \item \textbf{FAISS + LinUCB drill recommendations}: The 5-dimensional mechanical embedding is indexed, searched, and ranked through both nearest-neighbour retrieval and contextual bandit arm selection.
  \item \textbf{Full user account lifecycle}: Email and Google OAuth registration, onboarding, username setup, profile management, streak tracking, and GDPR-compliant account deletion with cascading data removal.
  \item \textbf{Row-Level Security on all user data}: Every table in the Supabase schema enforces \lstinline|auth.uid() = user_id| policies.
  \item \textbf{Targeted test suite}: pytest covers API contracts, frame selection logic, context injection, observability fields, security invariants, and schema consistency.
\end{itemize}

\subsection{Technical Accomplishments}

The technically significant accomplishments of this project are:

\begin{enumerate}
  \item \textbf{Multi-signal shot detection}: Moving beyond simple heuristics to a fused state machine that derives its thresholds from each video's signal distribution substantially reduces false positives in release frame identification.
  \item \textbf{Confidence-aware scoring with AI override}: The two-layer scoring model---deterministic rule-based plus LLM holistic---handles the fundamental limitation of geometric mean collapse while preserving a deterministic fallback.
  \item \textbf{FAISS + LinUCB drill recommendation}: Implementing a full contextual bandit pipeline---embedding computation, index management, arm selection, and reward tracking---in a working mobile application represents genuine ML systems engineering.
  \item \textbf{Skill-tiered normative ranges}: Adapting assessment thresholds by declared experience level, traceable to peer-reviewed literature, grounds the system in established sports science rather than ad-hoc thresholds.
\end{enumerate}

\subsection{Architecture Validation}

The shared \lstinline|PipelineState| dictionary pattern proved highly effective during debugging. When the shooting side detection bug surfaced, the fix was scoped entirely to \lstinline|motion_analyzer.py| and the joint name lookup functions. No other stage required modification because each stage only consumed its own named keys from the state. The architecture paid for itself on that single bug.

The Pydantic $\leftrightarrow$ TypeScript contract requirement caught two real schema divergences during development---both cases where a backend field was renamed without a corresponding frontend update---as compile-time TypeScript errors rather than silent runtime failures.

\section{Limitations}
\label{sec:limitations}

\textbf{Monocular pose depth.}
MediaPipe's depth estimation is inferred, not stereo-captured. Three-dimensional mechanics (side spin, wrist snap direction, elbow drift in the $z$-axis) cannot be reliably measured from a single camera.

\textbf{Single-frame event detection.}
The state machine identifies discrete events (frames) rather than continuous trajectories. For very fast releases or poor-frame-rate videos, the detected release frame may be off by several frames, affecting metric accuracy.

\textbf{Absence of a formal evaluation dataset.}
Rigorous quantitative evaluation of detection accuracy and metric validity against ground-truth biomechanical measurements was beyond the project scope. The system's correctness is grounded in the biomechanics literature and validated against a small development corpus, not a statistically representative sample.

\textbf{Analysis persistence race condition.}
If the client application crashes between receiving the completed analysis result and calling \lstinline|/api/analysis/complete|, the analysis is not persisted to Supabase. The SQLite job store retains it for 72 hours, but recovery requires a functioning client. This is a documented architectural issue with a planned resolution.

\textbf{Unauthenticated routes.}
Several endpoints (\lstinline|/api/history|, \lstinline|/api/user|, \lstinline|/api/feedback|, \lstinline|/api/recommend|) currently lack authentication middleware. This is an architectural gap identified in the production-readiness audit and documented for remediation.

\section{Practical Value}
\label{sec:practical_value}

What SHOOTRZ actually delivers is specific: a player records a five-second clip of a jump shot, uploads it, and within 30 seconds receives a numerical score, an explanation of what drove that score (per-metric verdicts with angle values), and natural-language cues from a large language model that has been informed of the player's recent analysis history. The player can ask a follow-up question in the chat, request a drill recommendation targeting the weakest axis, and compare their next analysis score against the previous one.

This is not a replacement for a skilled human coach. A coach watches game film, reads body language, and adjusts instruction in real time. SHOOTRZ serves a different and complementary function: it gives players objective frame-level evidence about their mechanics in practice sessions where no coach is present---which describes the majority of actual training time for any player outside a professional programme.
